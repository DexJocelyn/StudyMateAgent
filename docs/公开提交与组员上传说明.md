# 公开提交与组员上传说明

## 交给组员什么

`StudyMateAgent-组员上传源码.zip` 是完整可运行源码，不含密钥、数据库、虚拟环境或本机截图。课程报告保留已上传博客园的在线图片地址。每位成员拿同一个版本即可，不需要自己拼装模块。解压后的项目根目录应直接看到 README、backend、frontend、scripts、tests等。

每名成员的专用包也包含完整源码，另附 `docs/本成员交接说明.md`，列出对应模块、复测建议和应记录的材料。说明是工作入口，不代表该成员已经独立编写了所有相关代码。提交作者与实际贡献由本人确认，不替他人制造提交记录。

## 放到哪个仓库

课程主要成果统一在：https://github.com/DexJocelyn/StudyMateAgent 。个人仓库如需展示，建议使用独立的项目仓库，避免覆盖用于个人主页介绍的同名仓库 README。可以Fork团队仓库，也可以把完整源码上传到自己的项目仓库，并注明来源。

当前提供的是文件源码包，不带其他成员的Git历史。不要将ZIP文件本身当作全部源代码提交，也不要只传自己负责的一两个文件，那样不能单独运行。

## 使用 Git 上传到自己的项目仓库

先在GitHub准备自己的项目仓库。已有文件的仓库先克隆，再把源码合并到克隆目录，保留原有文件和历史；不要强制覆盖分支或删除原仓库内容。

在克隆目录中执行：

```bash
git status
git add README.md .gitignore .env.example requirements.txt requirements.lock backend frontend scripts tests docs
```

再把需要的macOS或Windows根目录启动脚本加入暂存区。检查 `git diff --cached --stat` 和实际内容后，用本人的Git身份提交并推送到自己确认的分支。分支名称以实际仓库为准，不默认覆盖其他人的main。

使用GitHub网页上传也可以，但要上传解压后的目录和文件，不上传私人运行目录；文件较多时分批提交。检查 `.gitignore`、`.env.example` 和 `frontend/vendor/` 没有漏掉。

## 运行

完整步骤见根目录README。Python需要3.11以上版本，各自创建本机虚拟环境。默认演示模式可以先检查网页和工具；真实模型、搜索需要在本机 `.env` 填入各自获授权使用的密钥。

组员的本地数据库是独立数据。要一起查看同一份任务，需要访问同一个运行中的课伴服务；把代码传到GitHub不等于自动部署网站。

## 提交前看一眼

- 保留 `.env.example`，不要上传 `.env` 或 `.env.share`。
- 不上传 `data/`、私人迁移ZIP、`.venv/`、`.tools/`、缓存、运行日志。
- 不上传本科背景调查等个人申请材料。
- 保留第三方库许可证，不随意修改依赖锁定版本。
- README及报告的公开链接、图片应可访问，分工和心得由本人核对。
