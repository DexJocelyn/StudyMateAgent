# 课伴：作业要求解析与交付自查

更新时间：2026-11-01。交付检查已整合回课伴的小组项目流程：作业要求 → 分工与执行 → 时间安排 → 交付检查 → 补充任务。首页恢复AI协作与任务/日程，本模块位于当前项目的交付环节。

## 用它做什么

输入老师要求，添加已写好的报告等材料，得到逐项检查建议。每项显示老师要求的原文、材料原文及行号、模型判断与补充建议。程序核对引文确实存在；覆盖程度、质量和最终是否合格仍由人工判断。

- 找到文字依据：存在相关文字，不能直接当作已满足要求。
- 材料中未找到：仅指此次提供的文字，没有判断其他文件是否存在。
- 需要人工确认：资料不足，或需要看图片、访问链接、实际运行等。

## 实际操作

1. 启动课伴，打开本机首页 `http://127.0.0.1:8000/`，进入项目工作台。`/tasks`仍兼容旧链接。
2. 点“新建项目”，填写名称、本人和可选成员。各个环节共用这个项目，不再另建自查空间。
3. 展开首页“已保存的作业要求与检查进度”，点击“查看或保存老师要求”，保存原始要求。点击“按要求准备分工”可返回原项目，把要求放入AI输入框；补充截止时间后手动发送，再检查并采用分工草案。
4. 执行任务和安排日程后，从同一项目点击“检查作业”，上传实际完成的材料，核对保存的正文。
5. 点击“运行真实AI自查”。使用主机现有千问配置，会消耗模型额度；页面显示实际等待时间，不显示内部思考。
6. 对照引文核对每项结果，选择“人工确认”或“需补充”，写备注后保存。人工确认是复核记录，不替代老师评分。
7. 标记需补充后，点击“生成补充任务”，明确负责人、未来截止时间和预计耗时，确认后写入真实任务库。点击已创建任务的链接返回同一项目，自动定位任务；切换为负责人视角后可更新状态。
8. 工作台显示本轮检查、待复核和未完成补充任务数量。任务完成不会自动把交付项标记合格，仍需人工复核。可导出自查报告，刷新恢复已保存状态。

两个页面间的项目编号通过链接明确传递，不只依赖本机上次选择。回到工作台会恢复当前成员的聊天草稿；未保存的要求、材料或复核文字会提示先保存。

老师要求或材料变更，会增加版本并将旧分析标为过期。旧结果仍可导出作历史参考，但不能继续复核或据此创建任务，必须重新自查。

## 文字与文件范围

支持UTF-8 TXT、Markdown、DOCX正文；单文件最多512KB，单份材料正文最多18000字，最多8份、总计48000字，作业要求最多12000字。

DOCX仅提取普通段落及表格中的正文，不读取内嵌图片、扫描页、批注、文本框等。PDF、图片、OCR和辅助批改尚未实现。不会自动打开文档中的链接，不读取GitHub仓库内容，不验证仓库是否公开可访问。

只上传愿意交给主机配置的模型服务分析的内容；不要上传密码、密钥等。分析只发送当前项目的要求与材料，不发送其他项目或原聊天历史。

## 怎么实现

前端提交保存后的材料 → 真实MCP工具`get_review_workspace`读取当前项目 → 千问返回结构化检查项 → 后端检查字段与逐字引文 → 真实MCP工具`record_review_analysis`再次校验版本并保存 → 前端逐项人工复核。

创建补充任务使用`create_review_task`。服务端检查最新材料版本、人工需补充状态、负责人和未来截止时间，并在事务中创建任务与检查项关联；同一分析项防重复，失败回滚。复核不会自动把旧任务标记完成。

新增三项MCP工具后共16项。模型密钥仍仅在HTTP后端使用，不传给MCP子进程。新数据表独立添加，不覆盖已有任务、会话或日程。

## 组员体验例子

老师要求：

```text
提交一篇项目报告。
报告需要说明目标用户和需求。
报告需要描述系统技术架构。
报告需附团队真实合照。
提供可公开访问的GitHub仓库链接。
```

已有材料：

```text
# 课伴项目报告
目标用户是大学课程作业小组，需求是检查作业要求与材料之间的缺项。
系统采用FastAPI后端、SQLite数据库，通过MCP连接工具，使用千问分析文字材料。
目前只有本报告，团队合照尚未准备。
仓库链接：https://github.com/DexJocelyn/StudyMateAgent
```

预期：目标用户与架构能定位到文字；合照不能被假称已核验；仓库链接可以找到，但“公开可访问”应留给人工确认。人工将合照标为需补充，再为某位成员创建一个拍摄/补充任务。

真实模型输出可能有差异；逐字引文校验能限制伪造证据，但不能保证模型没有漏项或解释错误。要对照原要求检查覆盖情况，重要提交仍需全员复核。

自动测试使用临时库与受控模型，不消耗额度。另做真实千问、MCP和浏览器验收，记录单独保存。原课伴的语音停止朗读问题、成员视角不等于个人账号等限制仍保留。

本次只修改Mac源码和本机运行服务，没有自动更新ROG、推送GitHub或重新开通公网入口。组员共用主机时只需主机配置模型；各自部署则需要自己的环境与密钥。公网共用一个访问口令，不是个人权限隔离；正式对外服务还需完善账号、项目授权、文件管理和部署。

## 简洁界面怎么用

首页只突出三个入口：

- 帮我分工：把老师要求放进对话输入框；补充截止时间后发送，确认草案后保存任务。
- 安排时间：先填写成员空闲时段，再点击“生成安排草案”，确认后保存。
- 检查作业：添加已有材料并按要求检查，确认缺项后创建补充任务。

管理成员、填写空闲时间、下载计划与重新开始对话收在右上角“项目设置”。任务筛选、已保存要求、检查进度和连接状态可按需展开。
