# 天气接口实现与报告说明

## 功能与使用

用户问“广州现在天气如何”，AI 应调用独立 MCP 工具 `get_weather`，读取结构化天气数据，简短回答天气、气温、数据有效时间及来源。问“明天广州会下雨吗”时，使用明天的预报和日最高降水概率，不将概率解释成确定下雨。

如果只说“现在室外几度”，先询问城市；系统不采集定位或从 IP 推测位置。同名地点返回候选列表，让用户确认国家或省份后继续查询。没有找到城市时可补充地点或尝试英文名，不猜测。

示例操作：

1. 进入自己的项目，选择自己的聊天成员。
2. 输入“现在天气怎么样？”；AI 应询问城市。
3. 回答“广州”；AI 应显示“查询城市天气”，随后给出结果。
4. 再问“明天广州最高最低温和降雨概率呢？”。
5. 刷新网页，检查天气来源链接仍保留，任务和日程没有被自动修改。

以上为验收步骤，不表示每个步骤都已经进行真实模型测试；实际结果见 `WEATHER_VERIFICATION.json`。

## 可用于报告的实现描述

本项目在原有课业协作 Agent 中增加了天气查询功能，采用“自然语言理解—MCP 工具调用—外部 HTTP API—结构化结果—自然语言回复”的实现方式。大模型负责识别用户的天气意图、城市和日期，天气数值由外部接口返回，而不是由模型凭知识猜测。

后端通过 Open-Meteo 地理编码 API 将城市名转换为经纬度，再调用 Forecast API，获取当前时刻的天气模型估计，以及当地今天和明天的预报。工具将天气代码转换为中文，并返回摄氏气温、体感温度、湿度、风速、数据有效时间、当地时区、每日最高最低温和日最高降水概率。应用在对话中展示实际工具执行状态及来源链接，来源随该项目成员的会话一起保存。

该功能体现了 Agent 对外部 API 的实际交互能力。API 提供天气数据，千问负责理解问题和组织语言；二者是不同环节。它是课业系统的辅助查询功能，不会因为下雨就擅自修改用户任务或日程。

## 技术路径

```text
用户：广州现在天气如何？
  → 千问选择 get_weather(city="广州")
  → MCP stdio 调用独立工具进程
  → GET geocoding-api.open-meteo.com/v1/search
  → 验证城市；同名地点需用户确认
  → GET api.open-meteo.com/v1/forecast
  → 校验字段、单位、时间和数值范围
  → 返回结构化天气数据
  → 千问生成回答；网页展示工具进度及来源
```

主要文件：

| 文件 | 作用 |
| --- | --- |
| `backend/services/weather.py` | 城市查询、天气 HTTP 请求、数据校验与错误处理 |
| `backend/mcp_server.py` | 注册 `get_weather` MCP 工具 |
| `backend/mcp_client.py` | 向模型提供工具定义；关闭功能时隐藏工具 |
| `backend/agent/runner.py` | 天气调用策略、同轮只读保护、来源保存 |
| `backend/agent/progress.py` | 展示“查询城市天气”状态 |
| `backend/main.py` | 健康接口返回天气配置状态 |
| `tests/test_weather.py` | 受控接口测试与模型工具循环测试 |
| `scripts/verify_weather.py` | 显式执行真实模型和天气 API 的独立库验收 |

## 接口、费用与数据性质

- 地理编码文档：https://open-meteo.com/en/docs/geocoding-api
- 天气文档：https://open-meteo.com/en/docs
- 使用条款：https://open-meteo.com/en/terms
- 数据来源署名：Open-Meteo，CC BY 4.0；对话附具体天气数据接口链接。

截至 2026-10-24，官方免费接口允许非商业教学用途，不需要 API Key；免费使用仍受供应商速率限制，商业化需重新评估条款。本实现不购买天气服务，不引入新的 Python 依赖，继续使用现有 httpx。千问生成回复仍消耗用户现有模型额度，不能把整个 Agent 说成永久免费。

Open-Meteo 当前天气是数值天气模型估计，不是学校门口的温度传感器，也不保证与天气 App 或现场温度完全一致。`data_time` 是数据有效时间，不是模型发布时间；`retrieved_at` 是本次查询时间。当前数据超过两小时或明显来自未来时标记 `fresh=false`，不能称作当前天气。今明两日预报按接口返回的当地日期回答。

## 边界与失败处理

- 只向固定的两个 HTTPS 域名发请求，不接受用户指定 API 地址或任意网页抓取。
- 仅发送城市名、必要地点筛选和经纬度，不上传聊天全文、项目任务或模型密钥。
- 城市参数、响应大小、超时、单位、温度范围及日期经过校验；不跟随 HTTP 重定向。
- 查无城市、同名歧义、限流、超时、网络失败或数据不完整均明确返回；失败不会捏造气温。
- 每轮最多三次天气工具调用。天气查询后同轮禁止写任务或生成草案，后续需要规划时由用户下一条消息明确提出。
- 本版本仅支持当前模型天气及今明两日预报，不声称支持任意历史日期、逐小时降雨时段、灾害预警或天气推送。用户问超出范围时应说明范围，不把现有预报套到其他日期。
- ROG 校园网是否能访问该服务需在 ROG 本机确认，Mac 成功不代表 ROG 网络必然成功。

## 测试证据的写法

自动测试使用受控供应商响应，验证字段解析、城市消歧、异常处理、任务不变、对话来源保存和模型工具协议；不能作为真实网络成功的证据。

真实验收脚本必须显式添加 `--run`，在独立临时数据库中进行一轮真实对话，使用少量模型额度。执行报告记录真实工具事件、原始回答、来源恢复与业务数据保持不变，并单独记录人工语义审阅，不把自动通过等同于模型回答完全正确。

```bash
python scripts/verify_weather.py --run
```

ROG 可先通过本机网页手动问一次，避免重复运行多轮脚本消耗模型额度。
