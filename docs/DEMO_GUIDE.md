# 课伴课堂演示流程

用一个独立的“课堂演示”项目展示真实模型、工具执行和数据变化。预计演示 5～8 分钟；模型等待时间随网络变化。语音另测，不将下面的文字演示计作语音通过。

## 开始前

1. 双击项目根目录的“启动课伴.command”，保留终端，打开 `http://127.0.0.1:8000/`。
2. 确认顶部显示“已连接模型”。如页面仍是旧版本，强制刷新一次。
3. 新建项目“课堂演示”，“你的姓名或昵称”填写“测试同学甲”，点击“添加组员”填写“测试同学乙”；创建后自动以测试同学甲的身份进入聊天。
4. 下面日期均用演示当天之后的明确日期替换；截止时间要晚于设置的空闲时间。

## 一 从要求生成草案

在聊天输入：

```text
老师要求小组开发一个能自然语言对话、实际调用工具的智能体，并提交需求描述、业务流、实现说明、演示和博客。我们做课业任务助理，有测试同学甲、测试同学乙两人。
请拆成4个最小演示任务，涵盖需求与业务流、模型与工具链、网页交互、测试与说明，每人2项，每项按30分钟估时。这些分工和估时已经确认。截止北京时间2026-10-25 22:00。
请生成待确认草案，不要直接保存正式任务。
```

讲解：“AI 根据需求提出任务草案；这时还没有往任务表保存。”检查草案负责人、工时和截止时间，点击“确认并保存”。切换“所有成员”筛选，看到四项真实任务；展开操作记录看到实际 MCP 调用。

## 二 从空闲时间安排日程

点击“设置空闲时间”，分别为两人设置 `2026-10-24 19:00` 到 `2026-10-24 21:00`。确认这是演示时刻之后、截止之前的时间。

发送：

```text
请根据已保存的任务和空闲时间生成日程草案，先不要保存，等我确认。
```

检查日程草案，确认后到“日程”查看。讲解：“排程由程序检查负责人、时段冲突、截止时间和工时覆盖，AI 不自行编造空闲时间。”

可选失败演示：在尚未保存日程时，先给每人只设置15分钟，要求排程，展示容量不足；补足时间后再生成可行草案。已有日程时调整空闲时间可能触发冲突保护，不要临时覆盖一份已排好的计划。

## 三 展示多轮指代与真实修改

选择当前成员自己的一个准确任务标题，输入：

```text
把我的任务「这里换成实际任务标题」标记为进行中，请实际更新。
```

随后依次发送：

```text
先暂停它，我有空再继续。
```

```text
现在继续它。
```

每一步检查卡片状态与真实操作记录。也可以使用卡片的“暂停任务”“继续任务”按钮。暂停记录状态，保留截止和已有日程，不表示倒计时或自动推迟计划。

## 四 完成任务并下载文件

发送：

```text
把它标记为已完成，然后导出当前项目计划，请实际执行这两个操作。
```

检查：同一个任务变为已完成、对应日程块移除、出现真实下载卡片。点击下载，打开 Markdown 文件，核对项目名、任务名和状态。

## 五 展示成员与刷新恢复

切到“测试同学乙”：对话分别保存，看板默认筛选乙的任务；小组任务依然共享。切回甲，恢复刚才对话。刷新网页，再次确认成员和历史仍在。

讲解：“这是本机成员视角切换，没有冒充已实现手机号或微信登录。”

## 语音单独验收

待演示设备就绪后：点击“语音输入”，允许麦克风，实际说出任务指令，检查转写文本再发送；核对任务实际变化；点击回复旁“朗读”，并测试“停止朗读”。记录设备、浏览器、原句、识别文本和实际任务变化。此项尚未完成实机验收。

## 录屏应保留的证据

保留原始输入、待确认草案、确认后的看板、真实工具记录、暂停/继续状态、日程、下载文件、切换成员和刷新后的对话。不要录制 `.env`、模型密钥或账户控制台。
